## Assumptions

1. "Enhance the UI" means the one page at `/`: the drop zone, the player, the runbook column,
   the footer, and the export button. The Markdown export is text and has no styling; the
   Logfire view is Pydantic's.

   app surface, so it takes the app-context choices the reference makes explicit: 6px square
   buttons, hairline cards, mono eyebrows, the grey text ladder. It does not get a hero, a

3. The page's behaviour is fixed by spec 001 (FR-018 to FR-022) and by the tests in
   `tests/test_render.py`: two columns, the five states, row click seeks and pauses, flagged
   rows expand to the note, four badge states with error distinct from flagged, export

   checked by eye on `modal serve` with the SAP sample; the last task is a rehearsal, not
   code.
5. No build step, no framework, no CSS file. The page stays one HTML file with a `<style>`
   block, because that is what `web` serves today and adding a static route means touching
   `app.py` and `CLAUDE.md` for no visible gain.

## What the reference says

Tokens from the `DESIGN.md` frontmatter and rules from its "Do's and Don'ts", numbered for
reference below.

- D1. Near-white canvas `#fafafa`, near-black ink `#171717` for headings, primary buttons,
  and borders. Text steps down a ladder: ink → body `#4d4d4d` → mute `#8f8f8f` → faint
  `#a1a1a1`. Never pure black.
- D2. Surfaces barely lift: white cards `#ffffff` with a 1px hairline `#ebebeb`, radius 12px.
  Shadow only for floating things (menus, tooltips). `#f2f2f2` for inset wells and hover.
- D3. Colour is reserved: blue `#0070f3` for links, focus, and success ("Success maps to
  `{colors.link}`"); error `#ee0000` / `#c50000`; warning `#f5a623` with soft `#ffefcf` and
  deep `#ab570a`. Accent colours never fill chrome.
- D4. Geist Sans for everything, Geist Mono for code and for the uppercase 12px eyebrows that
  label sections. Weight is binary: 600 headings, 500 buttons and labels, 400 the rest.
  Display type carries negative tracking: 32px at -1.28px, 20px at -0.4px.
- D5. Buttons split by context: black pills for marketing, 6px black squares (`button-primary-sm`,
  14px/500, `0 6px` padding) for nav and app controls. Ghost variant: white, hairline border.
- D6. Spacing on a 4px base: 8, 12, 16, 24, 32. Nav bar padding `12px 24px`, card interior 24px,
  input padding `8px 12px`, input radius 6px.
- D7. Nav bar and footer: canvas background, hairline top or bottom border, body-grey 14px text.
- D8. Mobile ≤ 640px stacks to one column; 768px keeps two-up grids.
- D9. The mesh gradient (develop `#007cf0`→`#00dfd8`, preview `#7928ca`→`#ff0080`, ship
  `#ff4d4d`→`#f9cb28`) is the only decorative system and lives in the hero. "Don't add a
  second decorative system."

Two things in the file itself need fixing when it is committed: line 60 has a stray sentence
after `fontWeight: 500` under `label-sm`, which breaks the YAML frontmatter, and the
`feature-card-elevated` entry is a duplicate of `feature-card` with no shadow value. Fix the
first; leave the second, we do not use it.

## Not planned, and why

- **A hero, pill CTAs, a logo strip, a CTA band.** Marketing surfaces; the reference itself
  says pills mark marketing and 6px squares mark the app. The page is the app.
- **Self-hosting Geist.** Needs a static route in `app.py` and a `CLAUDE.md` line for it.
  The Google Fonts link with `swap` falls back to Inter or the system sans if the venue
  network drops the request, and the layout does not depend on the font metrics. Revisit if
  rehearsal shows a flash of unstyled text that bothers you (open decision 2).
- **Dark mode.** The reference is documented light only; a second palette doubles the CSS
  for a room the projector will light anyway.
- **Badge flip animation, row entrance animation.** The reference's restraint: depth is a
  hairline, motion is nothing. The badges flipping one by one is already the animation.
- **Reworking the steps grid into instruction sentences.** The runbook plan's "Not planned"
  covers it: the grid is the demo.
- **A design-token file shared with the templates.** The fragment carries no styles; all
  styles live in the page. One `:root` block is the token file.
- **The stray `Untitled` file at the repo root** holds a path to another `DESIGN.md` in
  Downloads and is unrelated. Left alone; delete it by hand if it is yours.
